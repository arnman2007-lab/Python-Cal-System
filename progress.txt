## Codebase Patterns

### General
- Settings are stored in ~/.calsystem/config.json as JSON
- Use get_settings() from calsystem.config.settings for accessing settings (cached)
- Use reload_settings() to reload settings after changes
- Database connection via get_db() returns singleton DatabaseManager
- UI dialogs go in src/calsystem/ui/dialogs/ directory
- PyQt6 dialogs should be modal and use QDialogButtonBox for standard buttons

### Command Bank Architecture
- **Purpose**: Maps generic Calsystem commands to device-specific SCPI commands
- **Location**: Standards tab → "Command Bank..." button, or right-click on standard
- **Generic names** defined in STANDARD_COMMANDS (models.py):
  - IDENTITY, RESET, CLEAR, OPC (control)
  - OUTPUT, OPERATE, STANDBY (calibrator output)
  - OUTPUT_AC (AC with frequency - uses {frequency}, {freq_unit} placeholders)
  - MEASURE_DCV, MEASURE_ACV, MEASURE_OHM, etc. (DMM)
- **Placeholders**: {value}, {unit}, {frequency}, {freq_unit}
- **Lookup flow**: Calsystem calls generic name → finds calibrator's command bank → returns actual SCPI
- **Example**: OUTPUT → "OUT {value} {unit}" for Fluke, "SOURCE {value}{unit}" for others

### Wiring Diagram Library
- **Purpose**: Show correct wiring diagram based on calibrator + section type
- **Location**: Libraries tab for adding images, Procedures tab for linking
- **Standard section types** defined in STANDARD_SECTION_TYPES (models.py):
  - DC Voltage, AC Voltage, DC Current, AC Current, Resistance 2W/4W, Frequency, etc.
- **Auto-lookup**: calibrator_model + standard_section_type → library image
- **Procedure sections** have: display name (custom) + standard_section_type (for lookup)

### Execution Flow (Run Test tab)
1. Select DUT, work order, procedure
2. Click "Start Session" → detects calibrators from workstation (only active standards)
3. Loads command bank for selected calibrator
4. For each NEW SECTION:
   - Shows wiring diagram FIRST
   - Confirmation dialog: "Verify wiring, click OK when ready"
   - THEN sends calibrator output
5. For each test point: calibrator outputs → user enters reading → pass/fail calculated
6. On terminate/complete: sends STANDBY and RESET to calibrator

### Workstation Setup
- **Standards tab**: Add calibrators, DMMs, counters to workstation
- **Active checkbox**: Only active standards are scanned during session startup
- **Command Bank**: Each standard needs a command bank for automated control
- **Warning icon (⚠)**: Shown if standard has no command bank

### Reference DMM (HP 3458A)
- Test types: DMM_MEASUREMENT (no calibrator), CALIBRATOR_DMM (both)
- Unit conversion: 3458A returns base units (V), convert to test unit (mV)
- Commands: RESET, END ALWAYS, OFORMAT ASCII, DCV AUTO, TRIG SGL

### Measurement Target (Test Points)
- **Purpose**: Specify which parameter the reading should be compared against
- **Options** (MeasurementTarget enum):
  - PRIMARY (default): Compare reading to nominal_value (e.g., 5V)
  - FREQUENCY: Compare reading to frequency field (e.g., 100Hz)
  - CUSTOM: Compare reading to custom expected_value/expected_unit
- **Use case**: Testing AC voltage @ frequency - user may need to verify FREQUENCY reading, not voltage
- **UI location**: Procedures tab → Test Point Details → "Measure:" dropdown
- **Display**: When FREQUENCY or CUSTOM, nominal display shows expected reading + (CAL: output)

### Test Point Wiring Diagrams
- **Purpose**: Individual test points can have their own wiring diagram (override section diagram)
- **Field**: TestPoint.wiring_diagram_type references WiringDiagramLibrary.section_type
- **UI location**: Procedures tab → Test Point Details → "Wiring:" dropdown
- **Options**: "None" (default) or any section_type from the library
- **Execution flow**: If test point has wiring_diagram_type set:
  1. Load diagram from library
  2. Show confirmation dialog
  3. Then proceed with calibrator output
- **Use case**: Some test points need different wiring than the section default
  - Example: DCV test section but one point needs current input wiring to measure 0.2-0.33mA

### Custom Section Types
- **Purpose**: Allow users to add custom section types beyond the built-in list
- **Model**: SectionType table with name, description, is_builtin flag
- **UI location**: Libraries tab → "Section Types..." button
- **Management**: Dialog to view all types, add new custom types, delete custom types
- **Built-in types**: Seeded from STANDARD_SECTION_TYPES, cannot be deleted
- **Usage**: All section type dropdowns now use get_all_section_types() which returns both built-in and custom types

### Build & Deployment
- **IMPORTANT**: Always rebuild the exe after making code changes: `build_onefile.bat`
- The built exe is at `dist/Calsystem.exe` - this is what users run
- Source code changes do NOT affect the exe until rebuilt
- Config mismatch errors (e.g., "Extra inputs not permitted") usually mean exe is out of date
- Resources (images, templates) go in `resources/` folder - already bundled by PyInstaller
- For bundled resources, use `sys._MEIPASS` when `sys.frozen` is True (see execution_tab.py for example)
